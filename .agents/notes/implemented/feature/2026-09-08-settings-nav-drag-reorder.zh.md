# Agent Note: 用户自定义的设置分区导航顺序

Status: implemented

[English](2026-09-08-settings-nav-drag-reorder.md) | 中文

## 问题

每个功能插件都以自己的 `order` 值把设置页注册进 `settings.section` 账本。随着插件数量增长，Settings 面板左侧的导航栏混杂着各自随意、互不协调的位置：用户无法把常用页面提到顶部、也无法给相关页面分组，每个新插件还可能落在作者自选的位置。

## 决定

设置外壳（ui-settings-general）允许用户把导航行拖拽成自己的顺序，并持久化到用户设置文档中的新 `ui-settings-nav` 命名空间（`{ order: string[] }`），由本包的宿主端注册。外壳通过共享的 `ctx.settingsScope` seam 绑定该命名空间——不新增网络读取，与其它 GUI 偏好（主题、语言、对话）走同一边界。导航投影把持久化 id 叠加到插件声明的 `order` 之上：列出的 id 按所列顺序排在最前，已无有效注册的失效 id 被丢弃，重复 id 被合并，用户固定布局之后新注册的分区追加到末尾而非挤掉已固定位置。没有持久化顺序时，投影与之前按插件顺序的排序逐字节一致。

交互采用导航行上的 HTML5 拖放（沿用 workspace 浏览器的既有模式）：整行可拖拽，悬停到另一行的上半/下半区显示 2px 插入线，松手时通过注入的 `setSectionOrder` 回调提交当前可见的完整 id 序列。拖拽状态保持为面板组件的局部状态；写入走 scope，其回显通过现已包含命名空间 revision 的缓存键重新投影。行上没有抓握图标或其它可视手柄来标示可拖拽——提示来自拖拽光标与插入线。

## 备选方案

**把顺序存进带 localStorage 持久化的浏览器本地 store。** 否决：其它持久化 GUI 偏好都走用户设置文档（跨机器、由提供方持有、经 schema 校验）；第二条持久化通道会偏离既有的偏好机制。

**让每个分区保留自己的插件 `order`，只存一个索引扰动。** 否决：插件作者持有 `order` 且可能在其下改变它；完整 id 列表让用户布局拥有权威且无歧义，末尾追加规则保证未来插件不会违反它。

**在拖拽之外再加键盘排序操作（上移/下移）。** 延期：HTML5 拖拽没有键盘路径，但逐行操作会改变导航的界面框架与文案面；纯拖拽的缺口已记入包 README 的「已知限制」。

## 后果

- 导航顺序持久化在用户设置文档（`ui-settings-nav.order`）中，重启与插件重载后仍保留；卸载又重挂的分区回到其固定槽位。
- 非回环（远程）浏览器保持现有 scope 行为：内存模式下写入为空操作，顺序只在该会话内有效——与其它偏好行完全一致。
- 新插件的分区在用户移动它之前渲染在末尾，因此插件 `order` 不再是唯一的布局权威。
- 外壳的导航投影缓存键现在同时包含 scope revision、分区账本与 locale revision；合并助手 `applyNavOrder` 是带直接单元测试的纯函数，投影/写入装配由 shell 测试覆盖（满足每文件 100% 覆盖率门槛）。
